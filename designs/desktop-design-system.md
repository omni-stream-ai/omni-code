## 1. 桌面使用目标

桌面端用于持续查看任务、输入复杂指令、检查工具结果与处理审批。优先保证项目上下文、会话内容和执行反馈同时可见，通过稳定分区和适度密度减少页面往返。桌面布局独立设计，不把手机界面等比放大。

共用的规则包括品牌资产、语义颜色、字体家族、业务状态与文案。桌面单独规定导航结构、内容宽度、组件密度、指针与键盘行为。字体不因桌面信息更多而整体缩小；深浅主题均需独立验证。

## 2. 窗口与响应式布局

断点取决于应用窗口的可用逻辑宽度，不取决于显示器物理分辨率。下表为设计目标；当前源码存在多个断点，实施前需统一。

| 可用宽度 | 布局目标 | 收缩策略 |
|---|---|---|
| 小于 900 | 紧凑单栏 | 主内容优先，导航通过抽屉访问；触屏遵循移动热区 |
| 900–1199 | 紧凑桌面 | 默认 76 导航栏与主内容，项目及会话上下文按需展开 |
| 1200–1439 | 标准桌面 | 232 导航侧栏与主内容；辅助详情使用临时面板 |
| 1440 及以上 | 宽桌面 | 可按任务加入 320–400 辅助面板，保证主内容至少 640 |

侧栏展开宽度 232，折叠宽度 76。窗口不足以容纳所有区域时，先收起辅助面板，再折叠导航；不得把会话正文压成窄条。宽度小于目标最小内容宽度时退回较少栏布局。辅助面板仅展示已有能力所支持的内容，不由此新增文件树、终端或编辑器功能。

当前依据：`lib/src/responsive/app_responsive_layout.dart` 定义 900 / 1200 断点和 232 / 76 侧栏；`AppNavigationScaffold` 的默认断点为 1180，可被调用方覆盖。这些是现状记录，不代表所有页面已统一。

窗口尺寸、系统字体放大和面板状态共同决定布局。放大后若内容拥挤，应降低栏数；不能仅依据未缩放的窗口宽度保留多栏。

## 3. 页面骨架

| 区域 | 结构 | 规则 |
|---|---|---|
| 导航侧栏 | 品牌、全局路由、最近项目、最近会话、次要入口 | 项目和会话选中态区分；长列表独立滚动；折叠后入口仍有标签提示和无障碍名称 |
| 内容顶栏 | 页面或会话标题、项目上下文、必要动作 | 内容区高至少 56；原生窗口保留系统标题栏与拖动区域 |
| 主工作区 | 页面主体或连续会话 | 页边距 24，区块间距 24；内容优先，减少重复卡片 |
| 可选辅助区 | 当前结果、审批详情或已有上下文 | 与主内容有明确分隔和关闭入口；关闭后焦点回到触发处 |
| 会话输入区 | 草稿、附件、输入设置、发送与执行操作 | 固定在会话主栏底部，与消息保持同一阅读对齐线；不横跨辅助栏 |

不默认引入可拖动分栏；若后续增加，需定义最小宽度、键盘调整、重置和持久化。当前仅将已有侧栏折叠能力纳入设计。

## 4. 内容宽度与密度

| 类型 | 目标 |
|---|---|
| 工作台、项目概览 | 主容器最大 1200，居中；摘要可分栏，按任务分组 |
| 会话正文与输入 | 阅读容器最大 880，主体正文 16 / 26；不要铺满超宽屏 |
| 设置表单 | 表单最大 760；标签与说明对齐，长帮助文本可换行 |
| 代码、日志、Diff | 可使用主栏可用宽度；13 / 20 等宽字体，局部横向滚动 |
| 标准按钮与输入 | 最小高 40，控制圆角 12，水平内边距 12–16 |
| 高频工具栏按钮 | 最小高 36，图标 18–20；触屏模式至少 44 |
| 图标操作 | 指针操作热区至少 36 × 36，触屏至少 44 × 44 |
| 列表行 | 单行至少 40，双行至少 60；内容放大后增长 |
| 卡片 | 圆角 16，内边距 16–20；同类摘要对齐 |

桌面紧凑尺寸是对移动尺寸的限定覆盖，只适用于指针明确可用的环境。混合输入设备、触屏或不确定输入方式时使用至少 44 的操作热区，主要提交按钮优先 44。高密度用于工具和元信息，正文仍保持可读行高。

## 5. 核心页面

**工作台：**优先展示待审批、异常任务和最近会话。状态统计为紧凑摘要，不使用占据半屏的欢迎区。标准桌面可将会话与项目摘要分栏，信息顺序在窄窗口仍保持一致。

**会话：**侧栏保留项目与会话上下文，主栏连续阅读消息。当前阶段显示于关联区域，详细过程可展开；审批始终有可发现的入口。宽窗口可把用户主动打开的详细结果放入辅助区，关闭辅助区不丢失原始结果。输入草稿、附件与滚动位置不能因切换布局而重置。

**项目：**标题与主要动作对齐，长会话列表采用稳定列宽与清晰行分隔；是否显示排序、筛选、批量操作取决于现有能力。不能只为“像桌面软件”增加表格控件。

**设置：**分类导航与当前设置区分离，表单限制阅读宽度，错误贴近字段。选择分类后焦点与滚动位置明确；可用能力和保存反馈沿用业务规则。

## 6. 指针、键盘与焦点

可操作元素提供默认、悬停、按下、焦点、禁用、处理中与失败状态。悬停使用局部表面变化，不能只靠鼠标指针形状表明可点击。更多、复制等工具可以在悬停时加强显示，但键盘聚焦时也必须出现；关键操作始终可见。

Tab / Shift+Tab 按视觉顺序移动焦点。方向键只在符合语义的列表、菜单、标签页中使用，不能全局劫持正文滚动。Esc 优先关闭当前最上层菜单或弹层，不清空草稿、不退出任务。菜单或弹层关闭后恢复焦点；焦点框在两种主题下可辨认。

输入法组合期间 Enter 不得触发发送。发送与换行键位沿用现有实现或用户设置，并在输入区提供可发现说明；不得未经核对改成另一套习惯。Ctrl/Cmd+C、文本选择、系统快捷键保持正常。新增快捷键必须记录作用域、平台映射、冲突和界面入口，不能把草案快捷键标成已经可用。

右键菜单只能作为已有操作的补充，同一操作也需能通过可见菜单或键盘访问。Tooltip 提示短标签或现有快捷键，不承载审批风险和错误原因。异步结果更新不得抢走输入焦点。

## 7. 弹层、滚动与反馈

桌面简单确认采用居中对话框，建议宽 440–560；复杂配置可用 640–760，均受窗口宽度与 24 外边距约束。对话框最大高度为可用高度减 48，长内容滚动，关键操作始终可到达。底部弹层不作为桌面默认容器。

导航列表、会话正文与辅助详情可独立滚动，避免在同一阅读区域叠套多个纵向滚动容器。消息更新时仅在用户接近底部时自动跟随，否则显示新消息入口。代码和表格只在局部横向滚动。

状态反馈、审批生命周期、危险操作与无障碍对比度沿用基础规范。大屏不能成为把错误移到远处角落的理由；错误与重试仍放在关联任务或字段旁。全局连接状态需注明影响，不把旧数据表现成实时结果。

## 8. 设计与验收

先制作深浅两套桌面组件样板，再验证 1440 × 900 的工作台和会话核心稿；补充 900 × 700、1200 × 800、1920 × 1080 与小于 900 的降级布局。至少检查 200% 文字缩放、短窗口、长路径、长标题、密集输出、审批和断线失败。

验收要求：

- 侧栏、内容和辅助区有清楚边界，展开后主内容仍可读。
- 窗口缩放、折叠和页面切换不丢草稿、选择和任务状态。
- 键盘能完成导航、输入、审批与关闭弹层；焦点始终可见且不被遮挡。
- 鼠标、触屏和输入法组合均不误触提交，控件尺寸符合输入方式。
- 主栏无意外横向滚动，代码与表格可局部滚动；底部输入与操作不被窗口边缘遮挡。
- 深浅主题的正文、控件和焦点对比度达标，状态不只依赖颜色。
- 设计预览、源码能力与状态映射一致，未实现能力明确标为待实施。

当前完成仅为桌面规范草案。视觉方向确认、组件样板、核心页面、断点统一与 Flutter 实施均需后续完成；移动预览不能作为桌面验收证据。
