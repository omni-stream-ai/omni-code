# Relay 远程连接

[中文说明](README.md)

设置中的“Relay 远程连接”可登录 Relay、查看同账号下的 Omni Code 服务、申请访问并选择在线 Bridge。手机和桌面客户端不运行 Connector；它由提供服务的电脑端 Bridge 自动托管。

## 使用

1. 通过直连连接电脑端 Bridge 并完成原有客户端授权。
2. 展开“电脑端远程访问”，填写 Relay 地址和服务名称，选择“登录并开启远程访问”。在 Relay 网页登录自己的账号并批准显示的设备码。
3. 在需要远程连接的客户端设置中选择“登录 Relay”，用同一账号批准客户端设备码，再刷新服务并连接。
4. 电脑端可切换同账号自动允许或逐个批准，并批准、撤销、踢出及封禁远程设备。经 Relay 连接的客户端不能操作电脑端 Relay 配置或登记直连授权。

“使用 Relay 连接”开关选择当前传输；关闭后恢复保存的直连地址与凭据。Relay 账号会话、设备身份和选中服务与直连凭据分别保存。原生客户端沿用现有加密设置存储；网页使用当前浏览器的本地存储。设置导出或迁移时应把整个设置文件视为敏感文件。

设备登录最长有效 12 小时。过期或踢出后从设置重新登录，身份密钥会复用；不会把 Relay 拒绝当成 Bridge 的首次授权并自动登记直连凭据。退出登录会撤销 Relay 设备会话并关闭关联连接。服务离线、额度限制、禁止访问及业务错误不会触发写请求自动重放。

## 传输

HTTP、文件、SSE 和音频请求使用 /s/服务ID/业务路径。切换服务会取消旧 HTTP/SSE、在途响应和旧审批窗口，清理旧服务的列表、消息和 Agent 缓存，并重新订阅事件。Relay 明确拒绝登录、访问或额度后停止自动重连，用户在设置处理后重新连接。Bridge 返回的相对音频、上传地址保留服务路径前缀；音频播放器通过限定目标的请求客户端携带认证，并禁止凭据随重定向发送。

原生 WebSocket 携带 Relay Bearer。网页无法设置 WebSocket Authorization，改为先取得有效期 30 秒、限定目标路径和来源的一次性票据，再通过 WebSocket 子协议头完成认证；设备令牌不放 URL。票据不会转发给 Bridge。

网页 Origin 必须加入 Relay 的 CLIENT_ORIGINS。使用本地网页可固定端口：

~~~bash
flutter run -d chrome --web-hostname 127.0.0.1 --web-port 4173
~~~

独立部署的网页需配置自己的精确来源。自定义语音插件直接连接其提供方时，仍使用该插件自己的凭据；Relay 设备令牌不能发送给外部语音服务。

## 验证范围

新测试覆盖设备配对、按来源保存身份、服务筛选、访问申请、HTTP/SSE 认证、WebSocket 路径和票据限制、切换缓存及媒体凭据范围。现有设置、Bridge 和实时语音测试也需保持通过。

2026-11-08 已通过静态分析、174 项相关回归、原生资源代理真实 HTTP/WebSocket 测试和 Web 构建；网页 VAD 服务回归也已通过。omni-relay 的产品联调使用隔离账号和真实 Bridge，Chromium 窄屏完成登录批准、选择服务、保存并连接 Bridge；后端另覆盖 SSE、范围文件、较大 VNC 消息、重启与撤销。该测试不调用真实邮箱、模型或音频引擎。

公网真实邮箱、Android/iOS 真机、实际 ASR/TTS 引擎和长时间音频需要单独验收。原生远程桌面及证据媒体通过只开放当前资源路径的本机代理认证并加载，凭据不发送给 WebView，活动 HTML 与客户端账号存储分属不同来源。网页客户端目前不提供这类原生 WebView 资源入口。本地 Silero VAD 只在原生端加载；网页沿用 ASR 服务的语音事件，不加载 FFI。实际容器桌面与真机交互仍需单独验收。
