# MCP（Codex）

在设置中打开 **MCP · Codex**，或从 Codex 会话顶部的 MCP 按钮进入。设置页可选择 profile；会话入口使用该会话的 profile 和项目目录。

支持管理 stdio 和 HTTP 服务，编辑 JSON 配置、启用或停用、查看连接状态、重新连接，以及浏览和测试工具、读取资源和资源模板。配置保存回对应 Codex 配置文件，保留其他设置；并发修改会提示刷新，避免覆盖 CLI 的改动。自定义 profile 继承的服务可以创建覆盖，不能直接删除基础配置。

HTTP 服务可发起 OAuth 登录。手机或远程客户端完成授权后，如果浏览器无法打开 localhost 回调，将地址栏中的完整回调 URL 复制到登录对话框的回调输入框。Bridge 只接收当前登录签发的回调地址与 state。无需手动转交回调时，直接在浏览器中完成登录即可。

工具请求的表单和 URL 确认会显示交互窗口，可接受、拒绝或取消。工具结果支持 Markdown、结构化 JSON、图片、音频、附件下载和资源链接。工具测试会实际执行工具，应先检查参数。

此管理界面使用 Codex app-server 的 MCP 协议，需要 Bridge 所在机器安装兼容的 Codex。其他 Agent 继续使用各自的原生 MCP 配置。当前协议未暴露的 MCP 能力（如设备证明）不会伪造成功响应。配置变更后已有会话是否立即采用新连接，取决于 Codex 对运行中会话的重载行为；必要时重新连接或开启新会话。

验证使用隔离的临时 CODEX_HOME、本地 stdio/HTTP OAuth 服务和真实 Codex，不改写用户配置，也不调用模型。

状态页先读取配置和工具/认证摘要，展开服务时才读取完整资源目录；连接检查期间仍可管理配置。页面中的“测试连接”属于独立管理实例，“最近一轮对话”来自执行聊天的 Codex 实例。尚未观测到聊天实例时会明确提示未确认，旧对话不会根据测试连接推断为可用。

Bridge 每轮启动 Codex 进程。为避免慢启动的 HTTP MCP 被 Codex 默认的一秒启动窗口排除在模型工具列表外，Bridge 在用户未显式设置时使用 `mcp_optional_startup_grace_ms=30000`。这是最长等待窗口，服务就绪后立即继续；用户在配置文件中的显式值优先。服务自身的启动超时仍由其配置控制。
