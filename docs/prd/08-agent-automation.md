# 08 自动安装与配置

## 1. 执行摘要

用户说出目标后，系统应自动补齐工具与配置，而不是给出一串要求用户手动执行的命令。Codex、Pi 优先，其他 Agent 通过 ACP 扩展；可用 Agent 参与安装与配置，没有可用 Agent 时也有首次引导。

成功标准：标准路径无需手改配置文件；准备完成须经真实验证；重复请求不重复安装；原始任务只提交一次；失败可定位、可重试、可恢复。

## 2. 用户体验与功能

### TG-01 目标识别与就绪检查

**故事**：作为用户，我希望说“用 Codex 做这个任务”或“帮我接入某个 Agent”后，系统知道要准备什么。

**流程**：识别目标 Agent、宿主机和项目 → 检查安装、版本、登录、模型、配置、协议 → 就绪则继续，未就绪则生成准备任务。

**验收条件**：

- 优先使用用户指定 Agent；未指定时复用项目偏好，再推荐已就绪的 Codex/Pi；不静默切换。
- 不明确的名称、来源、目标机器或作用范围只询问必要信息，避免重复填写。
- 状态至少区分未安装、待配置、待登录、就绪和异常，并展示检查时间。
- 支持清单包含工具、平台、版本与接入方式；清单外工具标记未验证，不能承诺开箱可用。
- Pi 内嵌时不要求外装；是否可承担配置任务仍需验证模型与凭据。

### TG-02 按需启动与资源管理

**故事**：作为用户，我希望发任务时工具自己运行，结束后不长期占用无关资源。

**验收条件**：

- 环境就绪时无需提前打开终端或运行服务；本地进程按需启动，远端 ACP 自动连接检查。
- 同一目标的并发启动合并或协调，不产生冲突实例；健康实例在协议允许时复用。
- 列表刷新不启动完整任务运行时；探测有超时和资源清理。
- 活动任务不会被空闲回收；无任务实例按可配置策略释放，下次自动恢复。
- 客户端退出不终止已受理任务；运行时退出后区分安全重连、可续接和需人工处理。
- 无法控制远端服务启动时说明责任边界，提供诊断，不伪装本机已启动远端服务。

### TG-03 通过 Agent 安装指定 Agent 工具

**故事**：作为用户，我希望说“安装这个 Agent 并用于当前项目”后得到可执行结果。

**流程**：现有 Agent 检查平台、依赖和来源 → 形成计划 → 按权限执行 → 配置与验证 → 回到原任务。工具详情保留安装入口，调用同一流程。

**验收条件**：

- 显示目标开发机、工具、来源、预计作用范围及必要权限，用户不必选择底层包管理器。
- 优先复用兼容安装；升级或切换版本不静默破坏现有任务。
- 来源校验、下载、安装和验证分阶段记录；凭据、付款与提权按策略请求用户操作。
- 安装成功不等于就绪；验证版本、路径、认证和最小调用后才能完成。
- 其他 Agent 须完成可用的 ACP 接入；无兼容协议时明确显示限制。
- 失败保留进度及残留信息；取消后停止后续步骤，不自动提交编码任务。
- 安装不隐含卸载其他工具、变更默认 Agent 或安装无关依赖。

### TG-04 Agent 自动配置

**故事**：作为用户，我只提供系统无法知道的信息，其余由 Agent 处理。

**配置优先级**：复用合法可用配置 → 检测并生成 → 询问缺失信息 → 高级手动编辑兜底。

| 配置内容 | 自动处理 | 必要用户输入 |
| --- | --- | --- |
| 工具路径、启动方式与依赖 | 检测安装结果和平台，生成启动参数 | 多个合理安装之间的选择 |
| ACP 命令、参数、工作目录和端点 | 使用支持模板，探测并握手 | 无法推导的远端地址、访问授权 |
| 模型连接与默认模型 | 复用兼容配置，验证可用性 | 登录/API Key、必要偏好 |
| 项目和默认 Agent | 复用任务上下文及已保存选择 | 全局/项目范围等业务决定 |
| 受支持扩展 | 按 schema 生成并验证 | 扩展必需秘密或业务参数 |

**验收条件**：

- 标准路径无需手改 JSON、环境变量或启动命令；能检测的信息不要求重复填表。
- 配置前生成变更摘要并保留原值；按授权范围执行，不每个字段重复询问。
- 仅修改本次任务相关内容，发现并发变更先处理冲突，不覆盖无关配置。
- 写入后校验配置及最小实际调用；失败保留最后可用版本并提供恢复入口。
- 用户可查看生效值与来源、手动调整和恢复；恢复不等于卸载工具。
- 秘密使用专门输入或官方登录，不经普通聊天传递，不展示在变更差异中。
- 不静默切换模型供应商、开启付费或改变用户明确指定的工具。

### TG-05 首次没有可用 Agent 的引导

**故事**：作为首次用户，我不必先手动安装一个 Agent 才能获得安装配置帮助。

**验收条件**：

- 提供确定性的环境检查与基础安装引导，不循环依赖另一个未就绪 Agent。
- 有可用 Codex/Pi 时由其协助；没有可用模型时先完成必要登录或连接。
- 用户只完成无法代办的身份验证、权限批准和必要选择。
- 安装或登录取消后可从原步骤继续；凭据过期回到相应步骤，不清空所有设置。
- 网络不可用时解释缺口，可重试或使用明确的高级手动路径。
- 首次准备完成后执行最小验证，再回到用户原始任务。

### TG-06 准备任务状态、恢复与记录

**故事**：作为用户，我希望知道准备到哪一步，失败后继续而不是从头操作。

**状态**：等待检查、检查中、安装中、配置中、验证中、等待用户、已就绪、失败、已取消。无须的安装/配置步骤可跳过，跳过原因可查看。

**验收条件**：

- 展示工具、宿主机、阶段、已完成步骤、等待原因和可操作的下一步；详细日志按需展开。
- 准备任务有独立标识并关联原请求、项目、执行 Agent 与配置变更，和编码状态分开。
- 同一请求重试不重复安装或写入，目标变化时不误用旧结果。
- 客户端重连可继续观察，服务重启先核实环境，过期检查结果重新验证。
- 原任务仅在准备完成且未被用户取消时提交一次；失败保留需求和附件。
- 回滚失败、无法卸载的依赖和不可逆变更明确列出，不承诺全部自动撤销。

### 范围边界

本轮先支持 Agent 工具安装；任意开发工具安装后续评审。Bridge 的首次部署可使用引导说明，是否提供一键安装、开机自启与远程唤醒另行确定。未知来源工具不得因模型认为可用而加入受支持清单。

## 3. AI 系统要求

Agent 可调用受控环境检测、安装、配置、验证与诊断工具。配置对象有明确结构和范围，模型不直接获得无限宿主机权限。外部文档和安装输出按不可信输入处理，不能覆盖用户授权。

测试覆盖空白环境、已安装工具、多版本冲突、凭据过期、网络中断、安装退出成功但不可运行、配置写入失败、ACP 握手失败、并发请求和服务重启。最终验收核对真实环境，不只核对 Agent 回复。

## 4. 技术规格

准备任务持久化阶段、操作结果、配置备份和验证记录。安装与配置提供幂等控制、作用域限制、并发锁和取消机制；日志脱敏。准备任务与会话关联但生命周期独立，失败不能形成虚假的编码完成结果。

## 5. 风险与路线图

先实现就绪检查和确定性首次引导，再完成按需启动、受控配置与准备任务，随后打通 Agent 自然语言安装和首批 ACP 工具。工作包见 07。主要风险是安装来源、平台差异、误改配置和重试副作用，通过白名单、备份、范围授权与最小调用验证控制。
