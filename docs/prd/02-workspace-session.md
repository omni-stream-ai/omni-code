# 02 连接、项目与会话

## 1. 执行摘要

用户应从接入开发机顺畅进入任务，并在网络变化、跨设备切换或运行异常后继续工作。本模块以任务不重复、输入不丢失、状态不误导为验收重点。

## 2. 用户体验与功能

### WS-01 接入与设备授权

**故事**：作为用户，我希望在引导中连接开发机并完成授权，不必理解连接参数和终端命令。

**流程**：选择扫码/配对码接入，或展开手动地址 → 检查连接 → 展示宿主机与客户端身份 → 由宿主机所有者批准 → 进入项目。引导可提供可复制的宿主机准备步骤，记住已完成进度。

**验收条件**：

- 扫码与配对码承载限时配对信息，不直接暴露长期凭据；错误、过期、已使用分别提示。
- 等待批准、拒绝、网络失败和已授权明确区分；重进应用可继续未结束申请。
- 宿主机所有者可查看并撤销已授权设备；撤销后旧会话连接和后续请求失效。
- 修改地址先验证再切换；失败保留旧连接，切换时隔离缓存和凭据。
- 多设备授权不要求每次运行任务重新批准；身份或权限变化时再授权。

### WS-02 首页、导航与搜索

**故事**：作为用户，我希望首先看到待处理事项，并迅速继续最近任务。

**验收条件**：

- 首页优先显示待审批、等待输入和失败待处理任务，其次展示最近项目与会话。
- 支持按项目名、会话标题搜索；清楚标示搜索范围，分页加载不造成“无结果”误判。
- 筛选和排序可恢复；搜索为空、无匹配、加载失败分别展示。
- 深链和通知进入对应对象；对象不存在或无权限时可返回列表，不停留在死页面。
- 手机与桌面具有一致入口，返回导航保留列表位置和筛选。

### WS-03 项目创建、管理与详情

**故事**：作为用户，我希望选择开发机目录开始工作，并持续管理项目。

**验收条件**：

- 路径选择器显示开发机身份；支持选择已有目录或创建新目录，名称和路径有合法性校验。
- 提交前检查目录存在性、访问权限、重名与重复路径；失败保留输入并提示可执行的处理动作。
- 空项目也持久保存，重启后可见；展示路径、最近活动和可用的 Git 摘要。
- 支持修改显示名称、归档和取消归档；从列表移除不会删除宿主机文件。
- 会话和验收严格属于当前项目；无 Git 项目仍可运行任务，不伪造分支信息。
- 删除项目文件不放在普通项目管理操作中；若未来开放须单独定义权限与恢复方案。

### WS-04 历史、未读与跨设备继续

**故事**：作为用户，我希望看到真实历史，并知道哪些结果尚未阅读。

**验收条件**：

- 历史按稳定顺序分页，保留 Agent、模型、执行状态及产物关联。
- 只有实际展示的回复标记已读；其他设备读取后同步，不重复提示。
- 外部历史可展示来源及是否支持继续；不支持继续时允许新建会话并明确上下文传递范围。
- 宿主机、身份或项目切换不混入旧历史；恢复失败可重试。

### SS-01 发起任务与会话设置

**故事**：作为用户，我希望先说需求，系统用合适的配置开始执行。

**验收条件**：

- 项目内新任务复用当前项目；默认 Agent/模型使用已验证的偏好，用户可修改。
- 标题可自动生成且允许修改；启动命令、协议和模型地址不作为标准路径必填项。
- 缺少运行环境时进入 TG 准备流程，保留原需求，完成后仅提交一次。
- 同一创建请求重试返回同一会话；不同项目和 Agent 的冲突不能误合并。
- 模型和推理参数只展示当前 Agent 支持的选项，切换后的影响可理解。

### SS-02 消息、草稿与队列

**故事**：作为用户，我希望随时补充需求，断线或退出后也不丢失输入。

**验收条件**：

- 文本和附件可组合提交；相同文本的不同消息不误去重，同一发送请求重试不重复执行。
- 发送状态区分本地草稿、排队、提交中、已受理、执行中和失败。
- 草稿和未提交队列按宿主机/身份/会话持久保存；重启后恢复并展示待发送内容。
- 用户可编辑、撤回未提交队列；恢复应用不静默发送旧队列，须按用户已选择的发送策略处理。
- 执行中可选择排队或在 Agent 支持时补充当前任务，两种行为明确区分。
- 提交结果未知时先查询状态，不直接重新执行；凭据和临时授权信息不进入草稿缓存。

### SS-03 输入辅助与附件

**故事**：作为用户，我希望引用文件、命令和图片，不必记住路径或协议语法。

**验收条件**：

- 命令、技能与文件补全基于当前 Agent 和项目，支持键盘选择与空结果提示。
- 文件选择、拖放、粘贴能力按平台提供；纯路径文本不自动上传。
- 上传前显示文件名、大小、类型及限制；上传进度、取消、失败重试和移除均可操作。
- 不支持的文件类型或 Agent 图像能力在发送前提示，允许用户改用其他输入。
- 附件下载受权限控制；历史附件过期或被清理时显示原因，不出现无解释的空白。

### SS-04 阅读、差异与产物

**故事**：作为用户，我希望区分执行过程与最终交付，快速理解修改结果。

**验收条件**：

- 回合包含用户输入、阶段进度、工具活动、最终回复和产物；技术细节可展开。
- Markdown、代码复制、文件预览和差异展示归属正确；不能将计划修改显示成已落盘修改。
- 用户阅读历史时不强制滚到底部，提供新消息提示和回到底部入口。
- 图片/视频加载失败有替代操作；产物显示可访问状态和适用的下载入口。
- 失败回合保留已完成结果与未完成部分，不让局部失败抹掉所有内容。

### SS-05 连接与状态恢复

**故事**：作为用户，我希望断网、后台切换和换设备不会导致任务状态失真。

**验收条件**：

- 连接状态与 Agent 运行状态分别展示；客户端离线不能推断宿主机任务停止。
- 重连自动补齐状态与消息，不重复、不倒退、不串会话。
- 状态暂时无法核实时显示最后确认时间和“待确认”，不伪造完成或失败。
- 服务重启后标识原任务是恢复中、已中断还是可继续，提供对应操作。

### SS-06 执行生命周期

**验收条件**：

- 对用户呈现准备中、已受理、执行中、等待审批、等待输入、已完成、已取消、失败、状态待确认。
- 准备任务、编码回合和验收运行的状态分别管理；“已受理”不等于完成。
- 终态有时间与原因；迟到事件不能把终态错误恢复成运行中。
- 一个会话的执行并发按 Agent 能力约束，冲突时排队或提示，不静默覆盖任务。

### SS-07 停止、检查与继续

**故事**：作为用户，我希望长时间无输出时检查进展，再决定等待或停止后继续。

**验收条件**：

- 超过阶段提示阈值时显示无进展提醒，不据此自动判死；阈值可按运行类型配置。
- 检查返回正在执行、等待用户、不可检查或状态未知，并保留检查时间。
- “停止”与“停止后继续”分别说明效果，执行中防重复点击。
- 停止后继续先核实旧任务是否停止，再基于已完成步骤和原需求恢复；不能安全恢复时说明原因。
- 重复恢复请求不重复创建任务；旧页面不能停止已替换的新任务。

### SS-08 参数、回复与摘要

**验收条件**：

- 区分全局默认、项目偏好、会话设置和本轮覆盖，展示实际生效值及来源。
- 修改模型不会静默改变已执行回合；不可兼容时说明限制。
- 简短回复控制表达偏好，不截断关键错误、审批信息或验收结果。
- 摘要明确标为摘要，原文可查看；生成失败不影响原回复。

### SS-09 页面异常与恢复

**验收条件**：

- 加载、空历史、离线、上传失败、发送失败、待审批和恢复中各有适用操作。
- 失败保留输入与选择，重试不重复已完成工作；页面切换后的迟到响应不污染当前会话。
- 离开页面释放录音、播放等交互资源；不终止宿主机已受理任务。

## 3. AI 系统要求

会话展示真实工具结果，模型推测与已执行事实区分。上下文压缩保留原需求、关键决策和未完成事项，不能把摘要当完整历史。恢复时避免重复执行已有副作用的工具调用。

## 4. 技术规格

会话、消息、任务与附件使用稳定标识；持久状态为跨设备恢复依据，本地缓存按身份和宿主机隔离。写操作有幂等约束，状态同步可处理乱序、重复和缺口。项目及附件访问遵守 06 的授权和范围约束。

## 5. 风险与路线图

优先完成连接、任务和恢复闭环；配对引导、持久草稿队列与项目管理随后补齐。核心测试包括断网时提交、提交后丢响应、重连乱序、双设备操作、权限撤销、目录失效、取消与恢复竞态。状态及分期见 07。
