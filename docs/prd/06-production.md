# 06 生产要求

## 1. 执行摘要

生产发布以权限受控、任务可恢复、数据不串用和故障可定位为基础。下列要求是发布门槛；相关能力未满足时，应限制发布范围或关闭对应入口。

本章中的时间与容量为本版建议验收基线，发布前按首发平台和支持规模确认；未确定前不能宣称全平台生产可用。

## 2. 用户体验与功能

### NF-01 身份、授权与访问范围

**故事**：作为开发环境所有者，我希望只有获准设备能访问对应能力。

**验收条件**：

- 所有项目、会话、文件、上传下载、工具安装、插件变更、配置和验收操作统一检查身份及权限。
- 配对、健康检查、公开发布文件等例外显式列入清单，不能暴露私有路径或凭据。
- 授权设备可查看、撤销，长期凭据可轮换；撤销在后续请求及活动连接重新校验时生效，最长 30 秒。
- 文件访问规范化路径并限制到授权范围，符号链接和路径穿越不能绕过限制。
- 文件或证据链接限时、限对象、可撤销，不能仅依靠随机文件名保护。
- 远程生产连接使用加密传输或受保护隧道；不把明文公网地址作为默认接入方案。

### NF-02 秘密与隐私

**故事**：作为用户，我希望模型凭据和私有内容不会随任务日志泄露。

**验收条件**：

- 支持平台优先使用系统安全存储；服务端秘密独立保存并设置最小文件权限，不和普通设置混存。
- API Key、令牌、密码不进入聊天、通知、配置差异、诊断包、遥测或普通日志。
- 外部模型、云语音和推送的数据去向可查看，首次启用有说明。
- 用户主动分享日志或导出前可预览脱敏内容；秘密不因导出而转成明文。
- 扩展和自动配置不能自行读取无关秘密；临时授权到期清理。

### NF-03 一致性、幂等与恢复

**故事**：作为用户，我希望重试、断网和重启不会重复执行或错误显示完成。

**验收条件**：

- 创建会话、发消息、准备工具、恢复任务、审批和创建验收均有请求幂等语义。
- 丢失响应时先查询结果；不能保证副作用安全重试时转人工核实。
- 状态同步可处理重复、乱序和缺口；快照和事件不会相互覆盖较新状态。
- 服务重启后 60 秒内完成持久任务初步核对，无法核实的标记待确认，不静默丢失。
- 客户端、身份、宿主机和项目切换严格隔离缓存、草稿和订阅。
- 审批与取消竞态、恢复与新任务竞态有明确结果，不作用于错误回合。

### NF-04 性能、容量与资源

**故事**：作为用户，我希望应用能及时响应，并在资源不足时得到明确反馈。

**建议验收基线**：

- 在固定验收设备和局域网环境，普通按钮交互反馈 p95 ≤ 200 ms；首屏已有缓存内容 p95 ≤ 1 秒。
- 排除模型和外部安装耗时，任务受理响应 p95 ≤ 2 秒；超过时展示等待状态，不重复提交。
- 网络恢复后，正常规模会话状态收敛 p95 ≤ 10 秒；大历史分页不阻塞输入。
- 基线覆盖 1 台宿主机、2 个客户端、4 个活动编码会话和 1 个验收运行；正式容量不得由此外推。
- 编码、安装、下载和验收各有并发及资源上限；达到上限可排队或拒绝并解释原因。
- 下载、启动、工具调用、模型请求和资源租约均有超时；重试次数有限并可取消。
- 空闲资源回收不终止活动任务；磁盘不足时不继续写出损坏状态。

### NF-05 数据生命周期与备份

**故事**：作为用户，我希望知道数据保留多久，并可清理和恢复重要设置。

| 数据 | 默认策略 |
| --- | --- |
| 本地草稿与未发送队列 | 保留至发送或用户清理；撤销身份后不再可访问 |
| 临时上传与录音 | 未关联内容 24 小时清理；成功使用后 24 小时内清理临时副本 |
| 会话与关联产物 | 默认保留至用户删除，提供磁盘占用与清理入口 |
| 验收运行资源 | 默认最多 4 小时，超时先保存可得证据再清理 |
| 验收证据 | 默认保留 30 天，提前 7 天提示；支持导出、延长与删除 |
| 普通诊断日志 | 默认滚动保留 7 天并限制总大小 |
| 权限与关键变更记录 | 默认保留 90 天，可导出脱敏记录 |

**验收条件**：

- 运行中数据不被定时清理误删，引用与临时数据明确区分。
- 删除提示是否可恢复及影响范围；删除证据不会把原验收改成无证据仍完整通过。
- 配置变更有版本备份，升级前备份必要状态；恢复工具能验证可读性。
- 备份不包含无保护的秘密；密钥恢复限制向用户说明。
- 清理失败记录并重试，显示残留，不宣称已全部释放。

### NF-06 安装、更新与兼容

**故事**：作为用户，我希望工具和应用更新不会损坏项目或中断任务。

**验收条件**：

- 客户端、Bridge、Agent、ACP 协议与扩展维护支持矩阵，超出范围给出限制。
- 发布包、安装源和扩展验证来源及完整性；校验失败停止安装。
- 更新前检查活动任务和兼容性；可推迟，不静默中断运行。
- 数据迁移有备份和失败恢复步骤；不支持降级时提前说明。
- 版本不兼容时保留诊断与升级入口，禁用可能损坏数据的写操作。

### NF-07 可观察与故障处理

**故事**：作为用户，我希望看到可执行的错误处理方式，而不是只有错误代码。

**验收条件**：

- 错误展示失败阶段、已完成内容、影响范围和下一步，必要时附可复制追踪编号。
- 安装、配置、审批、任务恢复、验收结论和数据清理记录操作人、时间、对象与结果。
- 诊断包包含版本、能力状态、近期脱敏错误和资源信息，用户可预览。
- 遥测默认关闭，启用需说明并可撤销；关闭不影响本地诊断。
- 每个生产关键故障有处理流程：认证失败、模型不可用、任务状态未知、磁盘不足、升级失败、清理失败。

### NF-08 平台、无障碍与可用性

**验收条件**：

- 核心按钮具备可读标签、键盘焦点和状态文本，不能只靠颜色表达。
- 中英文界面和系统主题可切换；长文本、窄屏、虚拟键盘与字体缩放不遮挡核心操作。
- 平台不支持的能力隐藏或说明替代路径；不能展示可点击但无法完成的入口。
- 所有失败和空状态有离开或恢复路径；重试不丢已填信息。

## 3. AI 系统要求

所有自动化工具调用受宿主机身份和权限约束；外部文本不能提升权限。审批未知结果转人工，配置成功经真实验证，验收结论必须有证据。请求次数与费用可限制，达到上限暂停并提示，不静默换服务。指令注入、秘密泄露和越权样本纳入发布必测。

## 4. 技术规格

长期状态持久化，关键写入具备原子性或可恢复事务边界。秘密、业务状态和缓存分离；重要事件有稳定对象标识与时间。外部依赖故障隔离，不能因语音、遥测或更新服务故障导致核心文字会话不可用。

## 5. 风险与发布门槛

发布必须满足：

1. 确定平台、工具、版本与容量清单，清单内核心端到端用例全部通过。
2. 无未解决的越权、秘密泄露、跨身份数据串用、重复副作用执行或不可恢复数据损坏。
3. 断网、重启、取消、重试、撤销权限和磁盘不足演练通过。
4. 更新、备份恢复、资源清理和诊断导出演练通过。
5. 未满足完整体验的非核心入口关闭或明确限制；不能用“已开发”替代“已验收”。

时间与容量基线、保留策略作为建议产品默认值，正式发布前需与首发环境和存储预算一并确认。工作包见 07。
