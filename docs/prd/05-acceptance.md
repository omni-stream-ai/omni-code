# 05 自动化验收

## 1. 执行摘要

任务完成不等于需求满足。自动化验收将被测版本、测试计划、实际操作、证据与最终结论关联，让用户能检查刚完成的修改，而不是误测旧版本。

成功标准：每次验收明确被测内容；未确认计划不自动执行；无证据或无法检查不自动通过；AI 建议和用户最终结论分别记录。

## 2. 用户体验与功能

### AT-01 准备验收环境

**故事**：作为用户，我希望首次验收时系统自动检查并准备环境。

**验收条件**：

- 由任务内入口发起检查，展示依赖、磁盘和权限缺口；能自动处理的交给 Agent。
- 需要安装容器工具或额外权限时说明影响，按授权策略继续。
- 安装、验证、失败、重试状态持久保存；服务重启后核实环境，不假装已完成。
- 未就绪不能开始验收，但保留验收目标和计划草稿。
- 卸载前说明运行任务和证据影响，清理失败可继续处理。

### AT-02 创建验收与选择被测版本

**故事**：作为用户，我希望直接检查当前修改，不必先提交代码。

**流程**：从会话或项目发起 → 默认选择当前工作区快照 → 预览变更范围与排除项 → 冻结快照 → 生成计划。高级入口可选提交版本或其他明确版本。

**验收条件**：

- 默认包含当前已保存的未提交修改和允许纳入的新文件；不要求先 commit。
- 提交版本、工作区快照、未保存编辑内容有明确区别；未保存内容无法采集时提示。
- 开始前展示来源、快照时间、变更摘要及排除项；密钥、私有凭据和无关大文件默认排除。
- 冻结后使用稳定快照标识，运行中宿主目录变化不改变被测内容。
- 不具备快照能力时阻止继续或让用户明确选择可支持版本，不能静默改测 HEAD。
- 重复请求返回同一次运行；项目和关联会话必须一致。

### AT-03 环境识别、配置与复用

**故事**：作为用户，我希望 Agent 自动找到启动方式和依赖，失败后帮我修复。

**验收条件**：

- 优先自动识别；自定义镜像、构建文件和启动命令作为高级选项。
- 显示识别、构建、验证、启动各阶段及关键错误，必要时询问缺失配置。
- 复用基于运行依赖、环境配置和版本兼容性，不复用无关或过期环境。
- 用户可重建环境；旧证据仍关联原环境，不改写历史记录。
- 环境内使用专门测试凭据，权限范围和网络访问可控制，不默认继承所有宿主机秘密。

### AT-04 测试计划与确认

**故事**：作为用户，我希望先确认要检查什么，再开始自动操作。

**验收条件**：

- 计划来源于需求、修改摘要与用户重点，列出用例、步骤、预期和所需证据。
- 自动包含相关正常路径、关键异常路径与回归检查，说明无法自动验证的部分。
- 支持手动编辑和自然语言调整，版本递增，旧确认不能批准新版本。
- 关键字段缺失或计划过大时提示拆分，不静默截断。
- 计划未确认不执行应用操作；已确认计划发生实质变更后重新确认。
- 取消规划不等于验收不通过，更不等于通过。

### AT-05 执行、阻塞与结果分析

**故事**：作为用户，我希望看到每一项如何执行，并知道为什么通过、失败或受阻。

**验收条件**：

- 分别展示计划、环境准备、启动、执行、分析和等待确认阶段。
- 用例状态为待执行、执行中、通过、不通过、阻塞、未执行；阻塞和未执行不能算通过。
- 操作失败保留原始事实，重试次数有限；不能靠无限重试掩盖不稳定问题。
- 测试修改文件、调用外部服务或产生费用时遵守隔离与授权策略。
- AI 建议逐项引用证据，缺证据时标记无法判断，不给出无依据通过。
- 从缺陷返回编码会话时携带失败步骤、被测版本和证据；修复后创建新的验收记录。

### AT-06 人工接管

**故事**：作为用户，我希望自动化卡住时接管桌面，完成必要操作后交还。

**验收条件**：

- 获取控制权后暂停自动操作，同一时刻只有一个有效操作者。
- 展示控制者、租约和释放入口；断线后安全回收控制权，旧连接不能继续操作。
- 退出桌面后明确选择恢复自动执行、保持暂停或结束，不自动误继续。
- 桌面加载或输入失败可重试，手机键盘与方向切换适配当前平台。
- 敏感登录过程允许暂停录制或遮蔽，证据中标注缺口，不虚构完整录像。

### AT-07 证据、结论与清理

**故事**：作为用户，我希望回看证据并给出最终结论，知道资源何时释放。

**验收条件**：

- 截图、视频、日志和文本证据关联具体运行和用例；记录采集失败和缺失。
- AI 建议与用户最终通过/不通过分开保存；修改最终结论记录操作者、时间与原因。
- 用户可结束运行而暂不判定；超时和取消不冒充业务不通过。
- 停止后释放桌面、容器和临时网络；清理失败展示残留与重试入口。
- 证据保留、导出和删除有明确策略，过期前提示；访问链接限时且可撤销。
- 历史展示被测版本、计划版本、执行摘要、证据和最终结论；证据删除后保留必要元数据及删除标记。

### 范围边界

自动验收是决策辅助，不替代用户最终判断，也不默认操作生产环境。无法自动化的检查可转人工并记录，不为了闭环伪造结果。

## 3. AI 系统要求

验收模型基于可观察结果判断，必须引用证据；提示注入、页面误导文本、不可达应用、无证据和只完成部分步骤均作为失败评估样本。发布前关键样本不得出现无依据通过。质量评估同时报告错误通过、错误失败和无法判断，不能只报告总体成功率。

## 4. 技术规格

源码快照、环境、计划、执行与结论分别版本化。桌面控制有短期租约，证据访问有范围限制。任务重启、过期与清理有恢复机制；资源配额、超时和数据保留遵循 06。

## 5. 风险与路线图

先完成可追溯版本、计划确认、执行证据和人工结论，再扩展自动环境修复、复杂交互和连续回归。首批项目类型与浏览器/桌面能力需列入支持清单；不承诺任意应用均可自动验收。状态见 07。
