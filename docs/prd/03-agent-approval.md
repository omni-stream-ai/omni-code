# 03 Agent、模型与审批

## 1. 执行摘要

用户选择的是完成任务的工具，不应被迫先理解不同协议和配置文件。Codex、Pi 提供主要体验，其他 Agent 通过 ACP 扩展；模型与审批在统一界面管理，同时明确各 Agent 的能力差异。

成功标准：支持工具均有准确就绪状态；标准配置无需手改文件；所有执行遵守有效授权；未知或失败的审批不能被当作允许。

## 2. 用户体验与功能

### AG-01 Agent 发现与选择

**故事**：作为用户，我希望知道什么工具能用、缺什么，以及如何补齐。

**验收条件**：

- 默认展示 Codex、Pi；其他 Agent 从“添加 Agent”进入 ACP 引导。
- 每个工具显示未安装、待配置、待登录、就绪、启动中或异常，并提供对应操作。
- 已发现可执行程序不等于就绪；模型、认证和协议均完成验证后才显示可用。
- 优先复用用户明确选择；缺省推荐只基于可用工具，不静默切换用户指定工具。
- 内嵌 Pi 不要求安装外部 Pi CLI；缺模型时直接进入连接配置流程。
- 安装和自动配置遵循 TG-01～TG-06，不让用户离开任务寻找设置入口。

### AG-02 模型连接与选择

**故事**：作为用户，我希望复用已有可用模型，并在需要时添加连接。

**验收条件**：

- 优先发现原生已有连接和授权；只展示状态与必要信息，不回显秘密。
- 添加连接可输入自然语言目标，由 Agent 提议兼容配置；用户只补充地址、凭据等无法推导的信息。
- 保存前校验结构，保存后验证认证和最小调用；失败保留输入并说明是地址、网络、凭据还是模型问题。
- 模型列表只展示当前 Agent 可用候选；不可发现时允许手填并验证，不编造可用模型。
- 原生默认、推荐选择、显式指定三种模式可理解，展示最终选择和来源。
- 自动选择仅在启用且兼容的连接内进行；禁用连接不能被新任务显式或自动调用。
- 显式指定失败不静默切换；重试或切换会影响费用时告知用户并遵守已授权策略。
- 删除被引用连接前说明影响，允许替换默认值；正在执行任务不被无提示改配置。

### AG-03 ACP 扩展与能力发现

**故事**：作为用户，我希望添加其他 Agent，并得到一致且诚实的能力展示。

**验收条件**：

- 支持清单内工具可通过安装引导自动生成启动命令、参数和环境配置。
- 本地进程接入与远端服务接入分别展示；握手成功后记录工具版本和能力。
- 文字、附件、停止、继续、审批、命令等按能力开放；不支持项隐藏或说明原因。
- 工具不可达、握手失败、协议不兼容和认证失败可分别诊断并重试。
- 高级用户可编辑配置并验证；失败不覆盖最后可用配置。
- 原有会话保留来源；工具升级或接入迁移前验证兼容，不自动改变旧会话协议。

### AG-04 Pi 插件与扩展交互

**故事**：作为 Pi 用户，我希望添加扩展能力，并在会话内完成扩展要求的操作。

**验收条件**：

- 支持受信来源和用户明确提供的来源，展示名称、版本、来源、作用范围与权限需求。
- 安装、启停、配置、验证、更新和移除有独立状态；失败可重试或恢复上个可用版本。
- 全局与项目范围明确，项目扩展不加载到无关项目。
- 配置可由 Agent 协助，按 schema 校验；秘密使用专用输入，不写进普通配置摘要。
- 扩展确认、选择、输入等请求在当前会话呈现，响应只提交给对应请求；失效请求不能误作用于新请求。
- 不将扩展权限声明宣传为系统沙箱；执行能力与宿主机权限边界可查看。

### AP-01 人工审批

**故事**：作为用户，我希望理解即将发生的操作，按合适范围授权或拒绝。

**验收条件**：

- 审批展示目标机器、项目、操作、影响路径/命令、请求原因及适用风险说明。
- 优先提供单次允许、拒绝；会话或项目范围授权仅在明确支持且能表达范围时提供。
- 长期规则可查看、修改和撤销；不把“始终允许”解释为所有工具无限授权。
- 处理后显示服务端确认结果；重复、过期或已撤销请求不能批准新操作。
- 通知与会话内卡片指向同一审批；取消通知不等同于拒绝请求。

### AP-02 自动审批与人工回退

**故事**：作为用户，我希望常规授权按规则执行，不确定或越权操作交给我。

**验收条件**：

- 自动审批由用户启用，清楚显示作用范围、规则、风险阈值及模型连接。
- 确定性规则优先，模型仅辅助判断；显式拒绝和权限上限不能被模型覆盖。
- 模型超时、响应无效、风险未知或超过阈值时进入人工处理，不默认允许。
- 删除、覆盖、提权、外部传输、安装来源和付费行为按明确策略处理，不能只凭命令名称判定安全。
- 每次决定记录规则或建议、风险、原因与最终动作；秘密和完整敏感内容脱敏。
- 不同 Agent 只有在能可靠拦截执行前请求时启用对应自动审批，否则说明限制。

### AP-03 全局与项目策略

**故事**：作为用户，我希望给项目补充执行约束，又不影响其他项目。

**验收条件**：

- 区分硬性权限约束与给模型的背景提示；自然语言提示不宣传为确定性权限控制。
- 项目策略可细化默认策略，不能突破宿主机所有者设定的权限上限；冲突时采用更严格规则。
- 策略变更展示范围与生效时机；已运行操作不能通过事后修改伪装成曾获授权。
- 保存失败保留旧策略与编辑内容；项目规则不误写到全局。

### 范围边界

不要求所有 ACP 工具具备完全相同能力。平台或运行时无法提供权限拦截时不作等同承诺。账号注册、自动购买服务和任意未验证扩展不纳入标准免配置路径。

## 3. AI 系统要求

模型连接与配置建议必须通过真实调用验证。审批评估样本覆盖低风险查询、跨目录访问、破坏性操作、命令组合、指令注入、权限升级及超时故障；关键越权样本必须全部拦截或转人工才能发布。模型建议与最终授权分别保留。

## 4. 技术规格

工具注册信息包含身份、版本、来源、就绪状态和能力；连接凭据独立管理。审批有稳定请求标识、权限范围和失效机制。所有工具管理、扩展变更与配置读写遵守统一授权，审计记录见 06。

## 5. 风险与路线图

先完成 Codex/Pi 的就绪检测、模型复用和人工审批，再开放自动配置、ACP 支持清单及受控自动审批。旧接入迁移作为独立工作包，先评估历史与恢复兼容，再决定保留或迁移。状态见 07。
